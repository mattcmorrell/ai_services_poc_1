Mono Intent

Mono isn't for "small text" or "metadata." It's the visual signal that the agent is working, thinking, or produced this output. Everything else stays in the sans. Here's where it earns its place.

◆ The rule: If a human wrote it or would say it, it's sans. If the agent computed it, extracted it, or is actively doing it, it's mono. Mono is the agent's voice showing through the interface.

What Stays Sans
Not everything systematic deserves mono. Timestamps, step numbers, labels, navigation, buttons — that's UI chrome. The consultant's own messages. The agent explaining something in prose. Headings. All sans. Mono is reserved for the moments the agent's machinery shows through.
Mono — agent's work
Activity feed lines (agent narrating)
Thinking/reasoning blocks (agent's logic)
Tool call outputs (API responses)
Anomaly evidence data (agent's proof)
Inline data callouts (agent-extracted values)
Execution status badges (Done, Running, Gate)
Sans — everything else
Headings and titles
Chat message body text (even from the agent)
Step descriptions in action plans
Anomaly explanation prose
